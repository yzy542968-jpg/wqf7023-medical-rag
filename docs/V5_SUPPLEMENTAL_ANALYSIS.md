# V5 Supplemental Analysis

## Purpose and status

This document records analyses performed after the V5 quantitative freeze. The analyses read frozen cohort metadata, retrieval rows, and QA rows; they do not rerun a model, change a prompt, alter a threshold, change a fusion weight, change the selected cases, or overwrite `v5_statistics.json`.

The supplement has four purposes:

1. make the fixed Top-100 shortlist boundary visible;
2. report question-type sensitivity without replacing the pre-specified primary comparison;
3. disclose the report-section reference structure and cohort selection boundary; and
4. document a reproducibility dependency closure that is broader than the lightweight original freeze manifest.

The analysis was generated by `scripts/analyze_v5_frozen_supplement.py`. The output is stored in `experiments/post_submission_v5/v5_supplemental_analysis.json`.

## Cohort profile

The source file contains 3,851 processed OpenI/IU-Xray case records. The V5 builder first removes 1,260 case identifiers present in earlier project manifests, leaving 674 fresh cases that satisfy the V5 eligibility rule. It then selects 240 cases using the frozen seed, with 120 development cases and 120 confirmation cases.

Eligibility requires an image, at least 40 characters of findings text, at least 8 characters of impression text, an indication placeholder ratio no greater than 0.5, and a non-empty, non-`normal` problem field. This means the cohort is abnormality-enriched and should not be presented as a representative sample of all chest radiographs.

The processed source schema contains `case_id`, report sections, image references, and related metadata, but no stable `patient_id` or `subject_id`. The implemented partition is therefore a reproducible **case-level split**, not a verified patient-level split. The thesis must not claim that patient-level independence was established. A patient-level split remains a future improvement requiring a source identifier that permits it to be checked.

## Question-type sensitivity

The confirmation set contains 360 questions: 120 findings questions, 120 impression questions, and 120 summary questions. The summary question uses the impression text as its frozen reference. Consequently, the same impression content is represented twice per case in the aggregate QA metric. This is retained as a transparent property of the frozen benchmark rather than corrected after observing outcomes.

The descriptive final Token-F1 values are:

| Question type | Report-only | Multimodal | Difference |
|---|---:|---:|---:|
| Findings | 0.4101 | 0.4191 | +0.0090 |
| Impression | 0.4429 | 0.5079 | +0.0650 |
| Summary | 0.2158 | 0.2324 | +0.0166 |

The largest descriptive gain is in impression questions. This does not prove that the image branch is intrinsically specialized for impressions, because the questions share a case-level retrieval decision and the summary reference is duplicated. It does indicate that the aggregate +0.0302 final Token-F1 result should be discussed together with question-type composition.

After Holm adjustment within the final Token-F1 question-type family, the impression difference remains supported (`p_adj=0.0210`), while the findings (`p_adj=0.2541`) and summary (`p_adj=0.0696`) differences do not meet a 0.05 threshold. These adjusted values are exploratory and should not be promoted to new primary claims.

The paired question-type analyses in the JSON supplement use the same case-grouped bootstrap structure as the primary analysis. Their paired-randomization p-values are also reported with Holm adjustment within each question-type metric family. They are secondary and exploratory. They do not replace the frozen primary comparison.

## Top-100 shortlist ceiling

V5 performs BM25 retrieval over the 240-case candidate pool and applies image reranking only within the first 100 text candidates. An image cannot rescue a target that is absent from that shortlist.

The frozen retrieval rows show the following target availability at Top-100:

| Condition | Target recall at Top-100 | Targets outside Top-100 |
|---|---:|---:|
| Question-only BM25 | 42.50% | 207 / 360 |
| Indication + question BM25 | 98.61% | 5 / 360 |

The same shortlist membership applies before image reranking for the corresponding image conditions. This explains why indication ablation is methodologically important: it is not only a stronger baseline, but also determines whether the image branch is given an opportunity to rerank the correct target.

The primary multimodal comparison uses indication plus question as the text baseline, so the target is available to the image reranker for almost all confirmation questions. The Top-100 diagnostic does not invalidate the multimodal result; it defines the scope of what the result demonstrates.

## Random-image control integrity

The supplement confirms that the configured 100 image assignments are unique fixed-point-free derangements for the 120 confirmation cases. No image remains attached to its source case in these control assignments. The original V5 shuffled-image statistics remain unchanged.

## Logical cost accounting

The frozen confirmation run contains 360 questions. It therefore represents 720 logical BM25 query constructions: one question-only query and one indication-plus-question query per question. The corresponding image conditions reuse those text rows rather than issuing new text searches. The four deterministic retrieval conditions produce 1,440 recorded question-condition rows, while the 100 shuffled controls represent 36,000 lightweight image-reranking evaluations. The two downstream systems generate and semantically check 720 records in total.

This accounting separates logical workload from wall-clock time. Cached image and report embeddings make the shuffled controls much cheaper than repeatedly encoding pixels. The measured generation latency and GPU memory remain the more meaningful end-to-end costs in the current artifacts; retrieval-call counts alone should not be interpreted as production latency.

## Reproducibility supplement

The original `artifact_manifest.json` is intentionally lightweight and remains frozen. `scripts/build_v5_reproducibility_supplement.py` creates `experiments/post_submission_v5/v5_reproducibility_supplement_manifest.json`, which additionally hashes the V4.1 runtime configuration, source case file, semantic checker selection file, embedding and retrieval dependencies, answer metrics, and statistical helper.

This supplemental manifest improves auditability but does not retroactively change the original freeze claim. Model weights, image pixels, generated rows, and local caches remain subject to the repository's local-only policy and machine-specific environment.

## Interpretation boundaries

- The supplement is descriptive and sensitivity-oriented; it is not a new confirmatory experiment.
- The cohort is fresh relative to earlier project cohorts but remains from the same OpenI/IU-Xray source.
- Case-level separation is established by code; patient-level independence is not verifiable from the available processed fields.
- Report-level faithfulness does not guarantee that the selected report belongs to the frozen target case.
- Automatic Token-F1, support rate, and semantic verification are not clinical adjudication.
- The qualitative review remains exploratory and is not used to alter the frozen quantitative configuration.
