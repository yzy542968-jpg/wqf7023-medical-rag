# Dense Retrieval Plan

## Planned Model

The planned dense retriever is MedCPT:

- Query encoder: `ncbi/MedCPT-Query-Encoder`
- Article/document encoder: `ncbi/MedCPT-Article-Encoder`

The MedCPT model cards describe the query encoder as the encoder for short biomedical texts such as questions and search queries, and the article encoder as the encoder for longer biomedical text such as titles and abstracts. In this project, a radiology case is encoded as a document-like pair:

```text
title: indication + problem labels
abstract: findings + impression
```

This keeps the implementation aligned with the MedCPT two-encoder design while adapting it to radiology reports.

## Build MedCPT Index

After installing `torch` and `transformers`, build a small test index first:

```powershell
python scripts\build_medcpt_index.py --cases data\processed\openi_cases.jsonl --output data\processed\openi_medcpt_200_cases.npz --limit 200 --batch-size 4 --device cpu
```

Then evaluate it on the QA seed:

```powershell
python scripts\evaluate_medcpt_qa_retrieval.py --cases data\processed\openi_cases.jsonl --index data\processed\openi_medcpt_200_cases.npz --qa data\processed\openi_case_qa_seed.json --top-k 20 --output experiments\medcpt_qa_seed_eval_200_cases.json --device cpu
```

If the small test succeeds, build the full index:

```powershell
python scripts\build_medcpt_index.py --cases data\processed\openi_cases.jsonl --output data\processed\openi_medcpt_full.npz --batch-size 4 --device cpu
```

GPU can be used by replacing `--device cpu` with `--device cuda`.

## Why Keep BM25

BM25 should remain in the project even after MedCPT is available. It is a strong transparent lexical baseline, and it helps show whether dense biomedical retrieval improves over exact term matching.

## Current Dense Retrieval Result

The full MedCPT index has been built for all 3,851 OpenI cases:

```text
data/processed/openi_medcpt_full.npz
```

On the clean QA seed, standalone MedCPT achieved:

| Retriever | Hit@1 | Hit@3 | Hit@5 | Hit@10 | Hit@20 | MRR |
|---|---:|---:|---:|---:|---:|---:|
| MedCPT | 0.108 | 0.197 | 0.253 | 0.300 | 0.406 | 0.172 |

BM25 remains stronger than standalone MedCPT in this setup. However, hybrid BM25 + MedCPT improves over both standalone systems:

| Retriever | Hit@1 | Hit@3 | Hit@5 | Hit@10 | Hit@20 | MRR |
|---|---:|---:|---:|---:|---:|---:|
| BM25 | 0.231 | 0.344 | 0.383 | 0.428 | 0.486 | 0.297 |
| Hybrid, alpha = 0.25 | 0.247 | 0.361 | 0.403 | 0.453 | 0.506 | 0.317 |
| Hybrid, alpha = 0.50 | 0.242 | 0.378 | 0.422 | 0.478 | 0.553 | 0.324 |
| Hybrid, alpha = 0.75 | 0.228 | 0.344 | 0.397 | 0.478 | 0.558 | 0.311 |

Here, alpha is the MedCPT score weight after per-query min-max normalization. The strongest overall setting so far is alpha = 0.50 by MRR and alpha = 0.75 by Hit@20.
