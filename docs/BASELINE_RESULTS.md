## Interpretation

The TF-IDF and BM25 baselines are useful as transparent retrieval starting points. They already retrieve plausible cases for several disease-oriented queries, but they are limited by exact word overlap and do not understand medical synonymy well. BM25 performs slightly better than TF-IDF in the current keyword-qrels setup. The next retrieval system should use biomedical dense embeddings, planned as MedCPT with ChromaDB.

## Case-Grounded QA Seed Evaluation

A deterministic QA seed set was generated from 120 OpenI cases. Each case contributes three question types:

- Impression from indication.
- Findings from indication.
- Abnormality or normal-finding summary.

Current file:

```text
data/processed/openi_case_qa_seed.json
```

This set contains 360 questions. Each question is linked to one source case, so retrieval can be evaluated by whether the retriever returns the original case.

| Retriever | Hit@1 | Hit@3 | Hit@5 | Hit@10 | Hit@20 | MRR |
|---|---:|---:|---:|---:|---:|---:|
| TF-IDF | 0.189 | 0.267 | 0.281 | 0.308 | 0.342 | 0.232 |
| BM25 | 0.233 | 0.286 | 0.303 | 0.322 | 0.344 | 0.264 |

Output files:

```text
experiments/tfidf_qa_seed_eval.json
experiments/bm25_qa_seed_eval.json
```

These scores are lower than the keyword-qrels results because the QA seed asks more case-specific questions, often using indication-level information that is not unique to a single report. This makes the dataset useful for showing the limitations of lexical retrieval and motivates query reformulation, biomedical dense retrieval, and evidence-aware generation.

## Clean Case-Grounded QA Seed Evaluation

A cleaner QA seed was also generated by prioritizing non-normal problem-labeled cases and filtering out cases where the indication is mostly de-identification placeholders. The summary question was revised to include the case problem labels, making the question more useful for retrieval and RAG evaluation.

Current file:

```text
data/processed/openi_case_qa_seed_clean.json
```

This set also contains 120 cases and 360 questions.

| Retriever | Hit@1 | Hit@3 | Hit@5 | Hit@10 | Hit@20 | MRR |
|---|---:|---:|---:|---:|---:|---:|
| TF-IDF | 0.167 | 0.239 | 0.281 | 0.339 | 0.400 | 0.220 |
| BM25 | 0.231 | 0.344 | 0.383 | 0.428 | 0.486 | 0.297 |
| MedCPT | 0.108 | 0.197 | 0.253 | 0.300 | 0.406 | 0.172 |
| Hybrid BM25 + MedCPT, alpha = 0.25 | 0.247 | 0.361 | 0.403 | 0.453 | 0.506 | 0.317 |

| Hybrid BM25 + MedCPT, alpha = 0.75 | 0.228 | 0.344 | 0.397 | 0.478 | 0.558 | 0.311 |

The clean QA seed is the preferred prompt-pack source for the first LLM and RAG generation tests. The best retrieval direction so far is a hybrid BM25 + MedCPT retriever, because standalone MedCPT is weaker than BM25 but contributes complementary ranking signals when fused with BM25.

## Extractive Report-RAG Baseline

Before running full LLM-based RAG, an extractive report-RAG baseline was added. This baseline retrieves a case using TF-IDF or BM25 and then directly returns the retrieved case's findings or impression as the answer.

| System | Answer Token-F1 | Top-1 Case Accuracy | Non-Empty Answer Rate |
|---|---:|---:|---:|
| Extractive TF-IDF RAG | 0.488 | 0.189 | 0.986 |
| Extractive BM25 RAG | 0.341 | 0.233 | 0.967 |
| Extractive TF-IDF RAG, clean seed | 0.401 | 0.167 | 0.981 |
| Extractive BM25 RAG, clean seed | 0.364 | 0.231 | 0.981 |

Output files:

```text
experiments/extractive_tfidf_qa_seed_answers.json
experiments/extractive_bm25_qa_seed_answers.json
experiments/extractive_tfidf_qa_seed_clean_answers.json
experiments/extractive_bm25_qa_seed_clean_answers.json
```

The TF-IDF extractive baseline has a higher token-F1 despite lower case retrieval accuracy. This is likely because many radiology reports share repeated phrases such as normal chest or no acute abnormality. Therefore, answer token overlap alone is not sufficient for final evaluation. The final project should report retrieval accuracy, evidence support, and hallucination checks alongside answer text metrics.

## Agentic Evidence-Checking Hybrid RAG Baseline

An initial agentic RAG baseline was added on top of the best current retrieval direction, hybrid BM25 + MedCPT with alpha = 0.50. The agent performs query planning, retrieves complete case-level records, drafts an extractive answer from the retrieved report, checks sentence-level evidence support, and revises or abstains when support is insufficient.

| System | Answer Token-F1 | Top-1 Case Accuracy | Retrieved Case Hit Rate | Evidence Support | Revision Rate | Abstention Rate | Non-Empty Answer Rate |
|---|---:|---:|---:|---:|---:|---:|---:|
| Agentic hybrid RAG, clean seed | 0.412 | 0.242 | 0.422 | 0.992 | 0.008 | 0.008 | 1.000 |

Output file:

```text
experiments/agentic_hybrid_a050_qa_seed_clean_answers.json
```

Because the current agent draft is extractive, the evidence checker rarely needs to revise unsupported claims. This is a useful first safety baseline, not the final agentic result. The next thesis-relevant experiment is to use an LLM-generated draft answer and then evaluate whether the evidence-checking agent reduces unsupported medical claims compared with basic RAG.

## Qwen2.5 Small-Model Generation Pilot

A 30-question local pilot was run with Qwen2.5-0.5B and Qwen2.5-1.5B. The strongest current small-model setting is Qwen2.5-1.5B with hybrid BM25 + MedCPT retrieval and top-1 case-grounded prompting.

| System | Answer Token-F1 | Top-1 Case Accuracy | Retrieved Case Hit Rate | Average Answer Words |
|---|---:|---:|---:|---:|
| Qwen2.5-1.5B, LLM-only | 0.097 | 0.000 | 0.000 | 63.567 |
| Qwen2.5-1.5B, report RAG BM25 | 0.148 | 0.300 | 0.533 | 88.433 |
| Qwen2.5-1.5B, case RAG BM25 top-1 prompt | 0.209 | 0.300 | 0.533 | 52.900 |
| Qwen2.5-1.5B, case RAG hybrid top-1 prompt | 0.218 | 0.333 | 0.600 | 57.633 |

The pilot exposed a cross-case contamination failure mode: when the generator is given multiple retrieved cases, it may merge impressions from different cases into one answer. The top-1 case-grounded prompt and top-1 evidence checker were added to reduce this risk.
