# V16 Development Amendment R2

## Scope

This amendment records the post-screening validation expansion for the V16
generation-adaptation exploration. It does not modify V10, V11, or V15 frozen
artifacts, does not authorize Test evaluation, and does not constitute a new
confirmation protocol.

The initial V16 generation runs used a fixed 48-case Validation screening
manifest. The V10 Validation partition contains 384 cases, while the frozen
V12 ranking artifact contains complete findings/impression rankings for 376
of them. A deterministic 376-case manifest was therefore derived from the
ranking artifact before the expanded generation run. The eight Validation
cases without ranking rows are recorded as coverage limitations and are not
silently replaced.

## Screening decisions

The following predeclared development candidates were screened on the same
12-case subset and compared with the same frozen base-generation rows:

- balanced `qv`, 300 Train cases, 256 forward steps;
- balanced `qv`, 1,000 Train cases, 1,024 forward steps;
- frozen base generation with the output-policy pilot of 160 maximum new
  tokens and at most four complete sentences.

The 1,000-case adapter was not promoted from screening because its retrieved
history Token-F1 was lower than the 300-case adapter and its findings score
showed a marked deterioration on the screening subset. The output-policy
pilot was not promoted because it did not provide a stable paired improvement
and increased the token-ceiling rate under its larger generation budget.

The balanced 300-case QLoRA candidate remains the sole candidate selected for
expanded Validation comparison. This is a development screening decision,
not a claim of superiority on the full Validation partition.

## Expanded evaluation rule

The expanded run will compare the frozen base generator and the balanced
300-case QLoRA adapter on exactly the same 376-case manifest, with:

- the same frozen V12 ranking rows;
- the same target images, questions, and three history conditions;
- the original 96-token maximum and two-sentence answer bound;
- the existing paired Token-F1, contract, provenance, and ceiling metrics;
- full report-reference metrics only after row completeness is verified.

The 376-case run is still Validation-only development evidence. It may not be
used to retune the adapter, prompt, retrieval ranking, threshold, output
bound, or frozen V10/V11/V15 results. All comparisons remain automated
report-reference consistency measures, not clinical diagnosis accuracy,
clinical safety, physician agreement, or external validation.

## Manifest audit

The expanded manifest is generated by
`scripts/build_v16_validation_selection.py` from the existing V10 Validation
partition and frozen V12 ranking rows. Its summary records the source hashes,
the 384-case partition size, the 376-case ranking coverage, and the output
manifest hash. The generation runner requires the expected manifest size
explicitly, so a partial or accidentally substituted selection cannot be
treated as a complete run.
